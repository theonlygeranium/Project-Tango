# ADR: Control Mode — Voice-Driven Administrative Override

**Date:** 2026-08-20
**Status:** Accepted
**Decided by:** Writer Agent (WRITER Agent platform)

## Context

Project Tango personas have hardcoded system prompts defined in
`backend/personas.py`. Adjusting a persona's behavior, tone, or instructions
requires editing Python source code and restarting `tango-backend.service`.
There is no mechanism for the user to modify persona behavior mid-conversation
or at runtime.

The user requested a "Control Mode" that can be activated by speaking a
trigger phrase during a voice session, giving them administrative control to
adjust the persona's behavior, tone, or system prompt on the fly.

## Decision

Implement Control Mode as a voice-driven administrative override with the
following design:

1. **Phrase detection in `on_user_turn_completed`**: The `Jarvis` agent's
   `on_user_turn_completed` hook inspects each user turn's transcribed text.
   If it matches "Control Mode" (case-insensitive, with STT fuzzy variants
   like "control mood"), the agent enters Control Mode. "Exit Control Mode"
   returns to normal.

2. **Runtime instruction swap via `agent.update_instructions()`**: The LiveKit
   Agents SDK supports updating instructions mid-session. When entering
   Control Mode, the current instructions are stored and replaced with an
   administrative prompt. On exit, the original instructions are restored.

3. **Function tool for changes**: The `update_persona_behavior` function tool
   accepts a `change_type` (`tone`, `instruction_addition`,
   `instruction_replacement`, `behavior_rule`) and content. It applies the
   change to the live session via `update_instructions()` and persists it to
   PostgreSQL for future sessions.

4. **PostgreSQL persistence**: A new `tango.persona_overrides` table (migration
   006) stores active overrides per persona. At session start, `get_persona()`
   loads and merges them into the system prompt.

5. **Explicit exit only**: The user must say "Exit Control Mode" to return to
   normal. The agent stays in admin mode until explicitly told to leave.

6. **Master switch**: `TANGO_CONTROL_MODE` env var (default true) for fail-safe
   rollback.

## Rationale

- **`on_user_turn_completed` is the ideal interception point**: It fires after
  STT finalizes but before the LLM responds, giving us access to the
  transcribed text and the ability to modify the user message content.
- **`agent.update_instructions()` is the SDK-native way to change behavior at
  runtime**: No need for agent swaps or session restarts.
- **PostgreSQL persistence ensures changes survive restarts**: The user's
  adjustments apply to all future conversations, not just the current one.
- **Explicit exit prevents accidental mode loss**: The user maintains
  administrative control for as long as they need it.
- **Function tool approach lets the LLM translate natural language requests
  into structured changes**: The user says "be more formal" and the LLM calls
  `update_persona_behavior(change_type="tone", content="Always speak in a
  formal, professional register.")`.

## Alternatives Considered

1. **Slash commands in chat**: Rejected because Control Mode is primarily for
   voice interaction. The user should be able to activate it by speaking, not
   typing.

2. **Auto-exit after each change**: Rejected because the user may want to make
   multiple adjustments in a single Control Mode session. Auto-exit would
   require re-activating the mode for each change.

3. **Timeout-based exit**: Rejected for the same reason as auto-exit. A
   timeout could interrupt the user mid-thought.

4. **Full agent swap via `session.update_agent()`**: Considered but rejected as
   unnecessarily complex. `update_instructions()` achieves the same goal with
   less overhead and no need to reconstruct the agent.

5. **In-memory only (no DB persistence)**: Rejected because the user's changes
   should apply to all future sessions, not just the current conversation.

## Consequences

- A new database table (`tango.persona_overrides`) and migration (006) must be
  maintained.
- The `Jarvis` agent class now carries Control Mode state
  (`_control_mode_active`, `_base_instructions`).
- `get_persona()` has an optional `overrides` parameter that changes its
  return value when overrides exist.
- The `Jarvis` constructor now accepts a `db_pool` parameter for persistence.
- Changes made in Control Mode are cumulative and persistent. There is no
  undo — the user must explicitly request a reversal or the override must be
  deactivated in the database.
